# 情報漏えい等が起きたときの手順

不正アクセスなどで、利用者の情報が漏れた・漏れたおそれがあると分かったときに、上から順にやる。
プライバシーポリシーの「情報の漏えい等が起きた場合」（`/privacy`）に約束した内容と同じ順番にしてある。
落ち着いて、**記録を残しながら**進める（いつ・何を見て・何をしたか）。

---

## 1. 止める（分かってから数時間以内）

漏れた疑いのある鍵から順に差し替える。差し替えたら Cloudflare の再デプロイ（Deployments → Retry build）まで行う。

| 鍵 | 差し替え方 | 差し替えると起きること |
|---|---|---|
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase → Project Settings → API Keys で作り直し → Cloudflare の Secret を更新 | サーバーの処理が新しい鍵で動く |
| 全員のログイン | Supabase → Project Settings → JWT Keys で鍵を切り替える（または SQL Editor で `delete from auth.refresh_tokens;`） | **全員がログアウト**される |
| `TOKEN_ENCRYPTION_KEY` | `openssl rand -base64 32` で作り直し → Cloudflare の Secret を更新 → SQL Editor で `delete from public.user_tokens;` | 保存済みの Google トークンが使えなくなる。全員 Google カレンダーをつなぎ直す |
| `GOOGLE_CLIENT_SECRET` | Google Cloud Console → 認証情報 → OAuth クライアントでシークレットを追加 → Supabase の Google プロバイダと Cloudflare を更新 → 古いシークレットを削除 | 古い鍵でのトークン更新が止まる |
| `ANTHROPIC_API_KEY` / `OPENWEATHER_API_KEY` | 各サービスで作り直し → Cloudflare を更新 | 他人に使われて料金がかかるのを止める |
| `REVENUECAT_WEBHOOK_SECRET` / `REVENUECAT_SECRET_API_KEY` | RevenueCat で作り直し → Cloudflare を更新 | 偽の購入通知を受け付けなくなる |

Google のトークンが漏れた疑いがあるときは、上の `delete from public.user_tokens;` の前に、
利用者に「Google アカウント → セキュリティ → サードパーティ製アプリとの連携 → Imbrex → アクセス権を削除」を案内する。

## 2. 記録を確保する（止めるのと同時に）

ログは時間が経つと消える。**Supabase の無料プランはログの保存期間が短い**ので、最初に保存する。

- Cloudflare → Workers → home-public → **Observability**（アクセスとエラーのログ）
- Supabase → **Logs**（Auth・API・Postgres）
- RevenueCat → Integrations → Webhooks の送信履歴
- GitHub の最近のコミットと、誰が push したか

画面のスクショか、エクスポートしたファイルを、日付つきのフォルダにまとめて保管する。

## 3. 範囲と原因を調べる

- どの表の、どの利用者の、どの情報か（メール・表示名・予定・買い物・割り勘・写真・Google トークン）
- いつからいつまでか
- どこから入られたか（鍵の流出・設定ミス・コードの穴）

対象の利用者は SQL Editor で一覧にしておく（通知に使う）。

```sql
select u.id, u.email, u.created_at, u.last_sign_in_at
from auth.users u
order by u.created_at;
```

## 4. 個人情報保護委員会に報告する

不正アクセスが原因なら、**件数が少なくても報告が必要**（個人情報の保護に関する法律 26条）。

| 報告 | 期限 | 中身 |
|---|---|---|
| 速報 | 知ってから**おおむね3〜5日以内** | その時点で分かっていること |
| 確報 | 知ってから**60日以内**（不正アクセスなど不正な目的によるもの。それ以外は30日以内） | 原因・範囲・対応・再発防止策 |

報告は個人情報保護委員会のウェブサイトの「漏えい等報告」から行う。
迷ったら、委員会の「個人情報保護法相談ダイヤル」に相談する。

## 5. 利用者に知らせる

対象の利用者に、**速やかに**メール（`imbrex2026@gmail.com` から）で知らせる。アプリを開いた人にも見えるよう、
必要ならホームにお知らせを出す修正を入れる。

### 通知文の雛形

```
件名: 【Imbrex】お客様の情報に関するお知らせとお詫び

Imbrex をご利用いただき、ありがとうございます。
（日付）、不正アクセスにより、お客様の情報が外部に漏えいした（またはそのおそれがある）ことが分かりました。
ご迷惑とご心配をおかけしますことを、深くお詫び申し上げます。

■ 対象となった情報
（例）メールアドレス、表示名、アプリに登録した予定・買い物・家事の内容

■ 原因
（分かっている範囲で）

■ 当方の対応
・（日付）に不正なアクセスを止め、認証に使う鍵をすべて作り直しました
・個人情報保護委員会に報告しました

■ お客様にお願いしたいこと
・Google アカウントの「セキュリティ → サードパーティ製アプリとの連携」から Imbrex のアクセス権を削除し、
  あらためてアプリから Google カレンダーをつなぎ直してください
・不審なメールや連絡にご注意ください

ご不明な点は、このメールにご返信ください。
```

## 6. Google に報告する

Google のユーザーデータ（カレンダーのトークンなど）が関わる場合は、Google の
「API サービスのユーザーデータに関するポリシー」に従って Google に報告する。
連絡先と手順は、**何も起きていない今のうちに** Google Cloud Console のサポートとポリシーのページで確認し、ここに書き足しておく。

## 7. 再発を防ぐ

- 原因を直し、同じ攻撃が通らないことを確かめる
- `docs/data-and-privacy.md` に、何が起きて、何を直したかを書き足す
- 利用者と個人情報保護委員会（確報）に、再発防止策を知らせる
