# 公開版の機能とデータの取り扱い（2026-09-12 時点）

初回リリースは**課金なし**で出す前提。App プライバシー申告とプライバシーポリシーの
確認用に、いま実装がどうなっているかをまとめたもの。

## 1. 機能とその見え方

タブは状況によって出たり消えたりする。判定は2つだけ。

| タブ | 中身 | 出ない条件 |
|---|---|---|
| home | 今日のやること・家事・天気 | — |
| calendar | Google カレンダー + 手入力の予定 | — |
| cook | 献立カレンダー | **課金ゲート（初回リリースでは全員に出ない）** |
| shopping | 買い物リスト（共有 / 非公開） | — |
| split | 割り勘・固定費 | **1人世帯のとき（ソロ）** |
| recipe | レシピ | **課金ゲート（初回リリースでは全員に出ない）** |
| 設定 | 世帯・家事・カレンダー・アカウント削除 | — |

- **課金ゲート**: `household_entitled()` が `true` の人だけ。課金未実装なので全員 `false`。
  つまり初回リリースの利用者から見ると、**献立とレシピは存在しない**。
- **ソロ判定**: フラグではなく人数から導出（`memberCount <= 1`）。割り勘は2人前提のため。
- 購入導線（設定の premium 欄・ペイウォール）は `NEXT_PUBLIC_BILLING_ENABLED` が
  `true` のときだけ描画される。未設定の間は一切出ない。

## 2. データはどこにあるか

**保存先は Supabase（公開版専用プロジェクト）のみ。** 16テーブル、全てに RLS 有効。

| 種類 | 表 | 見える範囲 |
|---|---|---|
| 世帯・メンバー | households, household_members | 自分が属する世帯 |
| やること | shared_todos | 世帯 |
| 家事ルーティン | routine_definitions, routine_completions | 世帯（user_id は担当者） |
| 買い物 | shopping_items | 世帯。ただし `user_id` 入りは**本人のみ** |
| レシピ | recipes | 世帯（部屋をまたぐ） |
| 献立 | meal_plans | 世帯（部屋をまたぐ） |
| 予定 | local_calendar_events, calendar_settings | 世帯（user_id は作成者） |
| 割り勘 | split_sessions, split_subscriptions, family_card_totals | 世帯 + **現在の部屋のみ** |
| 日記 | diary_entries | **本人のみ** |
| Google トークン | user_tokens | 本人 + 同世帯のメンバー |
| 課金状態 | subscriptions | 本人（初回リリースでは空のまま） |

画像（レシピ写真）は Supabase Storage の `recipes` バケット。**公開URLで配信される**ため、
URL を知っていれば誰でも見られる。推測は困難だが、秘密ではない。

### 「部屋」による区切り

`households.pairing_started_at` が現在のペアの開始時刻。割り勘3表と共有買い物アイテムは、
この時刻以降の行しか見えない（restrictive ポリシー）。
**目的**: 1人に戻ってから別の人を招待したとき、前の相手とのお金の記録が新しい相手に
見えてしまうのを防ぐ。レシピ・献立・やること・家事は区切っていない（前セッションの
判断待ち。docs/handoff.md の「未決の設計判断 A」）。

## 3. 外部に出るデータ

ここが App プライバシー申告で申告が要る部分。

| 送り先 | 何を送るか | いつ |
|---|---|---|
| **Supabase** | 上記すべて、メールアドレス、認証情報 | 常時 |
| **Google** | OAuth ログイン、カレンダーの読み取り | ログイン時・カレンダー表示時 |
| **Anthropic (Claude API)** | **レシピURLのページ内容**、**レシート写真そのもの** | 取り込み・読み取り実行時 |
| **OpenWeatherMap** | **緯度経度** | home タブを開くたび |
| RevenueCat | 購入情報 | 初回リリースでは**送らない**（無効化済み） |

**見落としやすい点**:

- レシート読み取りは**写真を base64 で Anthropic に送っている**（`parse-receipt`）。
  レシートには店名・品目・金額・日時が写る。プライバシーポリシーに明記が要る。
- 天気は緯度経度を OpenWeatherMap に送る。座標が無い場合は
  `x-vercel-ip-latitude`（接続元IPから推定した位置）にフォールバックする。
  **Vercel 固有のヘッダーなので、別のホストに移すとこの部分は動かなくなる。**
- Google のリフレッシュトークンは `localStorage` にも置いている（`authStore`）。

## 4. 消すとき

| 操作 | 何が起きるか |
|---|---|
| アカウント削除 | `auth.users` から削除。外部キーが CASCADE / SET NULL に張り直してあるので連鎖する |
| 世帯の解散 | 抜ける人は新しい1人用世帯へ。レシピ・家事・やること・献立の**複製**を持っていく |
| 解散時のトークン | `user_tokens.household_id` を付け替える。**消すだけでは相手のカレンダーが見え続ける** |
| 解散時の非公開買い物 | **行ごと削除**する。`user_id` を null にすると「みんなのもの」になり中身が見える |

**Apple のサブスクはアプリから解約できない**（App Store Server API に該当エンドポイントが無い）。
課金を入れたら、削除画面で解約画面へ誘導してチェックを入れさせる方式になる。

### ⚠️ Guideline 4.8: ログイン方法が Google だけ

`AuthGate.tsx` は `signInWithOAuth({ provider: "google" })` のみ。

Apple のガイドライン 4.8 は、サードパーティのログインを主たるアカウント作成手段に
使う場合、**次の3条件を満たす別のログイン手段も用意すること**を求めている。

1. 集める情報が名前とメールアドレスに限られる
2. メールアドレスを隠せる
3. 同意なしに広告目的で追跡しない

**Google ログインはこれを満たさない。** 実質的に **Sign in with Apple の追加が必要**。
Supabase Auth は Apple プロバイダに対応しているので、実装量自体は大きくないが、
Apple Developer 側で Service ID と鍵の作成が要る。

**これは公開前に必ず対応が要る。** 現状のままだと 4.8 で差し戻される。
